# Databricks 開発手順

## 基本方針（Databricks公式）

- ソースコードはすべてGitで管理する
- 開発・検証・本番環境を分離する
- ローカルで開発し、Databricksでは実行・検証を行う
- テストを実施してからデプロイする
- 将来的にはDeclarative Automation BundlesによるCI/CDへ移行する

---

## 開発フロー

```text
Claude Code / VS Code
        │
        ▼
ローカルで実装・修正
        │
        ▼
GitHubへcommit / push
        │
        ▼
Databricks Git FolderでPull
        │
        ▼
Databricks Notebookで実行・検証
        │
        ▼
必要に応じてローカルへ戻って修正
```

---

## 開発手順

### 1. 最新コードを取得

```bash
git pull
```

---

### 2. Claude Codeで実装

- Pythonコード作成
- PySpark処理作成
- リファクタリング
- テスト作成

---

### 3. ローカル確認

- 構文チェック
- コードレビュー
- 必要に応じてpytest

---

### 4. GitHubへ反映

```bash
git add .
git commit -m "実装内容"
git push
```

---

### 5. Databricksへ反映

Databricks Git Folderで

- Pull

を実行する。

---

### 6. Databricksで動作確認

Notebookを実行し、

- Spark処理
- SQL
- Delta Table
- Unity Catalog
- エラー有無

を確認する。

---

### 7. 問題があれば修正

```text
Databricksでエラー確認
        ↓
Claude Codeで修正
        ↓
GitHubへpush
        ↓
DatabricksでPull
        ↓
再実行
```

---

## 運用ルール

- **コード編集はローカルで行う**
- **Databricksは実行・検証環境として利用する**
- GitHubをソースコードの正本（Single Source of Truth）とする
- Notebookには処理を書きすぎず、ロジックは`src/`へ実装する
- AIが生成したコードは必ず内容を理解してから実行する
